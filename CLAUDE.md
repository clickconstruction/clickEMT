# CLAUDE.md

Guidance for Claude working in this repo. README.md says what the app is and how to run it.

## Product rules

- **Two views, one truth.** The base (`index.html`) and the field app (`field/`) share `js/shared/`: `rules.js` (no DOM, no network: headings, zone codes, polygons, statuses), `data.js` (the only module that talks to Supabase) and `queue.js` (the field's outbox). A rule that both views must obey goes in `rules.js` or in the database, never in one view.
- **The database writes the log.** `ic_events` (the ICS 214) is filled by triggers on zones, photos, hazards, alerts and the incident. The apps insert only `note` events. If you add a kind of thing a unit can send, add its trigger in a migration.
- **Nothing is deleted.** Hazards are resolved, alerts are stood down, incidents are closed, zones are reopened, members are removed and put back. There is no delete path, and RLS has no delete policy. The one exception (v27) is personal data, never work product: `ic_clear_personal` blanks licences, dates of birth, addresses and licence photos and reduces evacuee records to "family of N" thirty days after an incident closes, by rule, on a date Operations can see.
- **Field first.** Every field action is one or two taps, works with gloves and rain, and goes through the outbox so a dead spot never loses a report. Ids are made on the phone before queueing, so a retry is harmless.
- **The front door (v33).** `index.html`'s `#auth` is the landing page (`.auth.landing`, styled in `css/base.css`; `.auth` itself is shared with the phone): the join code box (`#door-form`, `joinUrl` + `CODE_RE` from `js/shared/qr.js`, the same link a join card's QR carries), what the app is, the Try it cards and the sign-in form. Keep the form's ids (`auth-form`, `auth-email`, `auth-password`, `auth-signup`, `auth-msg`); `js/base/main.js` and the suites use them. A signed-in account never sees it. The screenshots in `images/front/` were rendered from the mock at v33 (the base at 1280 × 800, the phone at 375 × 812, both at 2×, light theme) with html2canvas-pro run inside the page, because the Browser pane's own screenshots are capped at the pane's width; the map tiles had to come through a CORS proxy and the headings' spaces swapped for non-breaking spaces before the render, or the renderer dropped them. Redo them when a screen changes.
- **The public demo (v32).** `/try/` frames the base and the phone on the in-memory stand-in with `?demo`, which the hook in `index.html` and `field/index.html` accepts on any host (`?mock` stays localhost-only, for the smoke suite). The stand-in replaces `createClient`, so nothing done in a demo reaches the real project. `_config.yml` therefore excludes `dev/` one pattern at a time (`dev/*.py`, `dev/*.mjs`, `dev/smoke.js`) rather than the directory, so `dev/mock-supabase.js` publishes; a new dev file that must stay unpublished needs its own line. The guides the page draws are `docs/guides/*.md`, which GitHub Pages serves raw. The tours are `try/tours.js`: each step names the frame, `show` (the element to ring), `do` (what to press, through the app's own buttons and forms, never the data layer, so the visitor sees the real UI react), `done` (read from the base's log or the frames) and `result`; `h.tap` takes a finder and re-finds the button at click time, because a live update redraws the panel or the log between the ring and the click. A step that drives a sheet must open it the way a thumb would; `h.act` (the hidden-button press the smoke suite uses) is for getting back to a known screen. The `demo` smoke suite runs one step for real.
- **Heading is part of a photo.** A photo carries the compass heading at the moment it was taken; the base draws the wedge. Never drop it to simplify.

## Stack

- Plain JavaScript ES modules, no build step, hosted as a static site. Leaflet 1.9.4 from cdnjs; the service worker caches it on first use.
- Supabase project `cjwybuhogxyayjnuxpem` (charity-tooling), shared with the charity app. Every table, function and policy of this app carries the `ic_` prefix. Owner-only RLS by incident membership: `ic_is_member(incident_id)` / `ic_is_ops(incident_id)`. The photo bucket is `ic-photos`, private, read through signed URLs.
- Apply migrations with `python3 dev/sbq.py supabase/migrations/<file>.sql` (the Management API with the Supabase CLI's saved login) and keep the file in `supabase/migrations/`. Rule tests go in `supabase/tests/` and must roll back.
- `config.js` is committed and holds only the public publishable key. Never put a secret key in it. Local overrides go in `config.local.js` (gitignored, localhost only).
- Sign-in is Supabase email and password. Field units check in to an incident with its six-letter code (`ic_join`); Operations creates incidents (`ic_create_incident`).
- Mock mode: `?mock` on localhost loads `dev/mock-supabase.js` before `supabase-client.js` (two lines in `index.html` and `field/index.html`, the only hook in the real app). It stands in for Supabase in memory, mirrors the migration's triggers (`afterInsert` / `afterUpdate`), column defaults (`DEFAULTS`) and policies (`allowed`), and seeds Cedar Fork Flooding with the base signed in as Operations and the field as Unit 3. Claude's browser pane cannot sign in to the real project (the credentials would go to Supabase), so this is how anything behind sign-in is exercised. When a migration adds a table, a column with a default, a trigger or a policy, mirror it in the mock and give the seed a row that uses it; when `data.js` gains a supabase-js call, add it to the builder. README.md says how to run it.

## Every release

1. Bump `VERSION` in `sw.js` when any shell file changes (cache-first). Add new JS or CSS files to `SHELL`.
2. `npm run check` (`node --check` on every JS file) and `npm test` (`dev/test-rules.mjs`, for `rules.js`). For anything the views do, run the smoke test against the mock: serve with `npm run serve` (dev/serve.py, which sends no-store so an edited file is what loads; the stock `python3 -m http.server` let the Browser pane keep a stale stylesheet for minutes; with no port argument it takes `$PORT`, which the Browser pane's `incident-map-any-port` launch config uses when 8766 is held by another checkout), open `http://localhost:8766/?mock` at desktop width (1280 wide) with no other mock tab open, and in the console `const { run } = await import('/dev/smoke.js'); await run()`. It takes two to three minutes; in the Browser pane start it detached (`import('/dev/smoke.js').then((m) => m.run()).then((r) => { window.__smokeResult = r; })`) and read `window.__smokeResult`. The pane must stay visible: the base redraws on `requestAnimationFrame`, which a background tab never gets.
3. Apply any new migration before pushing: the apps read the new columns on start.
4. Commit messages: a release is titled after the feature with the version in parentheses, matching `sw.js`.

## Gotchas

- GPS, camera and compass need a secure context: `localhost` or HTTPS. A LAN `http://` address on a phone gives none of them.
- iOS gives compass readings only after `DeviceOrientationEvent.requestPermission()` from a tap; `Sensors.requestCompass()` is called before the camera opens and from the menu.
- The camera is a file input with `capture="environment"`; the heading recorded is the compass reading when the picture comes back, not when the shutter was pressed.
- Realtime subscriptions use one filter per table (`incident_id=eq.<id>`); the incident row itself is filtered by `id`.
- Leaflet markers are `divIcon`s with `iconSize: [0, 0]`; CSS centres the marker on the point. Unit markers are kept and moved, everything else is redrawn on change.
- GitHub Pages serves the site from a subpath, so every link and import is relative; the field app registers `../sw.js`.
- Messages (`ic_messages`, `ic_message_acks`; ROADMAP slice 1): recipients are fixed on the message as `to_users` when it is sent (`Data.recipientsFor('all' | 'ops' | 'zone:<id>' | 'user:<id>')`), one ack row per recipient with a reply. `kind` is `message`, `safety` or `par`; a safety message takes over the phone until acknowledged and stays on the base's yellow bar (`openSafety()`) until every recipient has answered. Log kinds are `msg`, `safety`, `par`; log rows carry the class `log-<kind>` because the plain `.msg` class is the form message in shared.css.
- Accountability (ROADMAP slice 2): `ic_members.status` is `assigned`, `available`, `out_of_service` (with `status_note`) or `checked_out`, with `status_at`, `crew_count` and `agency`. The database sets it from assignments (`ic_zone_sets_status`), stamps and logs every change (`ic_member_before` / `ic_member_after`, log kind `status`), and a check-out gives the unit's zones back. A unit may update its own row, Operations any row. The PAR is a message of kind `par`; the answer is an ack with `reply` "All accounted for" or "Missing someone" and `count`; a missing report also raises an alert from the phone. Labels live in `rules.js` (`STATUS_LABEL`, `OOS_REASONS`).
- Operational periods (ROADMAP slice 3): `ic_periods` and `ic_objectives`; `ic_incidents.current_period_id` points at the open one and `ic_zones.objective_id` at the objective a zone serves. `ic_start_period` (ops only) closes the current period, carries open objectives into the new one renumbered from 1 and moves the zones with them, quietly (`ic_quiet()` reads the `ic.quiet` setting so the objective trigger stays silent); `ic_create_incident` opens period 1. `periodLabel()` in rules.js names a period the same way everywhere. The briefing is `briefingSections()` in js/base/ui.js, rendered as a page and as plain text from the same lines; `@media print` in base.css prints only `#briefing`.
- The Division assignment (ROADMAP slice 4): `ic_zones.work_assignment`, `instructions`, `channel`, `supervisor`; the log says "Division B-2 drawn" and "B-2 assignment updated". The printed 204 (`form204Sections` in js/base/ui.js) shares the briefing overlay: `state.printZone` picks which to draw. In code and the database a division is still a zone (`ic_zones`, `zone`); only the words on the base changed.
- The map on the paper (`js/base/print-map.js`, `divisionMapHtml`): the 204 and each division's 204 in the IAP carry the division as an inline SVG, OpenStreetMap tiles underneath as `<image>` elements (never a canvas, so a cross-origin tile can't taint anything; a tile that doesn't load leaves the plain ground, and the outline, north arrow and scale bar still work). A section may carry `figure` (HTML already built); `sectionsHtml` draws it after the lines and `sectionsText` leaves it out, so the text reports stay plain. The module builds strings only, so `dev/test-print-map.mjs` runs it in Node (`npm test`). The Print button waits for the tiles (`mapsReady` in js/base/main.js) before `window.print()`; `.kind-<kind>` on `#briefing-page` lets print CSS give each IAP division its own page. The scale bar is in feet and miles, like `milesText`. OpenStreetMap's tile policy requires the "© OpenStreetMap contributors" credit on every map; keep it.
- Search passes and structures (ROADMAP slice 5): `ic_zones.status` is `open`, `active`, `primary` (primary search complete) or `cleared` (secondary complete), stamped by `ic_zone_stamps`; a finished pass frees the unit like a clear. `ic_structures` is one record per address; `ic_structure_after` makes the zone's `cleared` the count of searched records and `structures` at least the record count, so once a zone has records the old tap counter is gone, and logs a notable record (people needing help, sheltering or refused, major damage, hazards). `Data.finishPass(zoneId, pass, {marking})` is how both views finish a pass. The field's "Address clear" is `openStructure()`; a structure placed from the base is `not_searched` until the field taps it.
- Facilities and the communications plan (ROADMAP slice 6): `ic_facilities` (kind, name, position, contact, notes, `closed_at`), ops only, logged by `ic_facility_after`; `ic_incidents.channels` is a JSON list of `{use, channel, notes}` logged by `ic_log_incident`. `FACILITY_KINDS` in rules.js carries the letter drawn on the map (every kind its own letter; a new kind goes in the SQL check, `ic_facility_kind_text`, the mock's check and `FACILITY_TEXT`, and a `.fmark-<kind>` colour in both stylesheets and print-map.js); `nearestFacility()` and `directionsUrl()` are what the phone uses, for each of `NEARBY_KINDS` (staging, boat ramp, shelter, hospital). On the facility card, Close puts the card away (`close-panel`) and Mark closed (`close-facility`, beside the Open badge) closes the facility. Placing is the map's `facility` mode: one click, then the panel opens to name it.
- Reports (ROADMAP slice 7): `ic_periods.sitrep` holds the situation report's words (`summary`, `needs`, `outlook`), logged by `ic_log_period`. One overlay (`#briefing`) draws the briefing, a division's 204, the situation report or the IAP: `state.print` picks which, `sitrepSections` / `iapSections` in js/base/ui.js build them from the same section lists as the briefing, and `.no-print` keeps the edit form off the paper.
- Agencies, public information and replay (ROADMAP slice 8): `ic_incidents.lead_agency` and `ic_periods.unified` are words, logged by `ic_log_incident` / `ic_log_period`; `commandText()` and `agenciesOn()` in rules.js say who is in charge and who is on scene from where, on the base's home panel, the field's menu and every report. `ic_photos.public_ok` is set by Operations alone (`ic_photos_update` policy), logged by `ic_log_photo_public`, and false on every new photo; `Data.publicPhotos()` is the Public Information Officer's set; "Download cleared photos" (`downloadPublic` in js/base/main.js) zips it with js/base/photo-export.js (no DOM, no library: stored entries, CRC32, the caption as XMP and a JPEG comment or a PNG iTXt; `dev/test-photo-export.mjs`). A caption names the division, never the coordinates. `ic_tracks` is written only by the `ic_positions` trigger (`ic_track_position`: every reported position, except the same spot again within a minute) and read only through `rpc/ic_replay` (one sample per unit per `p_every` seconds), never kept in the store. The base's Replay (`openReplay` / `drawReplay` in js/base/main.js, `setReplay` / `renderReplay` in js/base/map.js) fetches once per range, then the slider and Play only move `state.replay.t`; while it is on, the live unit markers are taken off the map and the photo pins are the ones taken by that moment.
- Light and dark (css/shared.css, js/shared/theme.js): every surface, border and tint is a token on `:root`, redefined under `:root[data-theme="dark"]` and under `prefers-color-scheme: dark` for `:root:not([data-theme="light"])`, and forced light again under `@media print`. The choice is per device (`localStorage` `ic.theme`), set inline in both pages' heads before first paint; the base's header button toggles it, the field's menu has three chips. Text in the accent colour reads `--accent-text` (lighter in dark), buttons keep `--accent`. The map tiles are dimmed in dark through `--map-dim` on the tile pane; the boundary and the draft outline read `--map-ink` / `--map-accent` through `getComputedStyle`, so a theme change redraws them. Ink that sits on the yellow safety bar or the hazard triangle stays `#1B1B18`; marker edges stay white.
- The activity log (js/base/ui.js `logHtml` and friends, `drawLog` in js/base/main.js): folded to its latest line or open, filtered by where a line came from (`LOG_GROUPS`, `logGroupOf`), searched, with the hours marked (`.log-sep`) and every line linked to what it is about (`logLink`). Folded or open and the group are a device setting (`ic.base.log`); lines newer than `state.log.seenAt` are counted on the header and tinted until the pointer comes over the log. Print 214 is the overlay's `214` kind (`form214Sections`, oldest first, the loaded events of the period only, `EVENTS_LIMIT`).
- Notable lines and the pop-out (v17): `ic_events.notable` is the one thing on a log line that changes after the database wrote it, set by Operations alone (`ic_events_update` policy; `ic_event_before_update` refuses any other change, and the mock mirrors both). The star on a row is drawn by CSS (`.nmark::before`), so the rows' text stays plain for copying and for the smoke test's `logTexts()`; the `Notable` chip is a `group` like the source chips (`inGroup` in ui.js), and `form214Sections` puts the marked lines first under their own heading, starred again in the full log. Pop out opens the same page at `#log` in a window named `ic-log`: `LOG_ONLY` in js/base/main.js skips the map, the sidebar and the bars (`drawAll` returns after the log), keeps the log open under its own prefs key (`ic.base.log.popout`), and the page's `log-only` class hides the rest. A line's link in the pop-out posts `{incident, select}` on the `ic-base` BroadcastChannel and the main window selects it. The smoke test stands the pop-out in as an iframe at `#log` (a script's `window.open` has no user gesture) and must remove it before the next suite resets the mock.
- People (`ic_people`, js/shared/rules.js `QUALIFICATIONS` / `qualsText` / `crewNames`, js/base/ui.js `peopleBoardHtml` / `personRowHtml` / `form211Sections`, the field's `drawJoinPeople` / `drawPeople`): a record per responder riding with a unit (`user_id` is the member whose phone it is), archived never deleted, with `qualifications` from the fixed list (the SQL check and `QUALIFICATIONS` must match; `ic_qual_text` in SQL and `qualsText` say the same words in the same order, so the mock's log lines equal the database's). Once a unit has people on record, `ic_members.crew` and `crew_count` are theirs (`ic_member_before` recomputes them on every member update; `ic_sync_crew` is the no-op update that triggers it, and a hand change is overruled, so the field's crew stepper is gone); with nobody left on record the count is unknown again. A unit's own check-out takes its people with it quietly (`ic.quiet`, no line per person), and a status change back from `checked_out` brings back the people who left with it (`checked_out_at >= old.checked_out_at`); `ic_join(..., p_people jsonb)` matches names on the unit regardless of case, checks them back in and adds the new ones. A unit writes only its own people; moving one to another unit is Operations' alone (the update policy's with check). The People board is its own overlay (`#people`, `state.people` holds the find text and the chips, AND across chips), redrawn on every change unless a field in it has focus, so a handler that changes it blurs first; the 211 is the briefing overlay's `211` kind, opened from the board. Report lines that start with two spaces are drawn indented (`p.sub`) under the line before; `sectionsText` keeps the spaces. The rule test is `supabase/tests/people.sql`.
- A message's urgency (`ic_messages.urgency`: `now`, `nightfall`, `tomorrow`, `blocking` or '') is the four words in `URGENCY` in rules.js, mirrored lower case by `ic_urgency_label` in SQL for the log line; `lat` / `lng` is the spot it is about. The field's Message Operations puts the urgency first, the suggestions under the box (hidden while the unit types) and a draggable pin on a small map; the base shows a badge, Show on map and a bubble pin (`placedMessages()`: waiting on someone or sent in the last two hours).

The choice is a device setting (`ic.map.layer`): the base's picker in the tools bar, the field's menu chips; both maps swap the layer in place (`setBaseLayer` / `setMiniLayer`). Only the streets tiles carry `tiles-dim`, which dark mode dims. Custom imagery is a picture by its corner coordinates (`bounds` `{south, west, north, east}`), ops only, archived never deleted, drawn in the `imagery` pane (z 250, under everything drawn) on both maps from signed URLs; `opacity` is shared, hiding is per device (`ic.map.hidden`). The mock draws a stand-in for a seeded overlay with no file (`aerialPlaceholder`).
- The right-click card for a division (`zoneModalHtml`, `#zone-dialog`, a native `<dialog>`): rank is the division's place in `data.zones()` (priority, then code); the priority buttons in it reuse `set-priority`, so the card and the rank follow live. The map's polygons and labels and the sidebar rows all open it on `contextmenu`; the map swallows the browser menu.

The field keeps a link's code in `sessionStorage` (`ic.field.join`) through sign-in, fills the check-in form with it, or opens the incident at once when the account is already on it, then forgets it; a link skips the "reopen the last incident" step. Scanning uses the browser's BarcodeDetector where it exists, else jsQR loaded only then; the Browser pane has no camera, so the scan sheet can only be seen refusing. The base draws the QR beside the code (`fieldJoinUrl`), prints a join card (overlay kind `join`), and its picker's join form takes `?join=` too. The `join` smoke suite decodes the base's own picture with jsQR.
- Identity (`ic_profiles`, bucket `ic-ids`, js/shared/licence.js): one row per account with name, phone, licence (number, state, expiry, date of birth, address as the barcode gives them), `id_source` (`scan`, `photo`, `typed`) and the front's photo at `<user_id>/licence.jpg`. `ic_join` refuses a unit without a name and a phone (`ic_profile_ready`, `profileReady` in rules.js; v25). A licence or its photo is the identity (`ic_profile_complete`, `identityGiven`) but not a condition: without one the check-in line ends ", identity not given" (`NO_ID_TEXT`), the resources row says "no ID", the unit panel and the 211 say "identity not given", and Operations verifies in person with the same Mark verified. The phone opens Identify yourself only when the name or phone is missing, and saves `id_source` '' when no licence was given. The phone's Identify yourself sheet opens before check-in when the profile is missing; its scanner reads the PDF417 on the back of a licence (`startScan` with `format: 'pdf417'`: the browser's BarcodeDetector where it has that format, else ZXing, loaded only then) and `parseLicence` reads the AAMVA records, month first for the USA and year first for Canada. The base's unit panel shows the identity, the photo from a signed link and Mark verified; the resources rows and the 211 carry the name. The mock draws a licence front for a seeded profile with no file.
- The Layers panel (`layersPopHtml` in js/base/ui.js, `drawLayers` / `setLayersOpen` in js/base/main.js, `#layers-pop` under the tools bar): the map underneath as radios on one side, the overlays on the other with a show box (per screen), an opacity slider (shared) and the upload form (`overlayFormHtml`, shared with the home panel's Map imagery section; `fillOverlayBounds` fills every such form from the map's view). A draw queued on a frame that never comes (the pane hidden a moment later) falls back to a 1.6 s timeout, so one missed frame no longer holds every later draw.

- Sections (`ic_periods.planning_chief` / `logistics_chief` / `finance_chief`, `ic_requests`, `ic_members.demob`, js/shared/hours.js): a period's five seats are plain names; `ic_start_period` takes all of them and the start form carries the last period's over, so an empty seat is a choice and prints as "not set". Hours (`hoursRows` / `hoursTotals` / `hoursCsv`) are pure: the window is the period, or for the whole incident the earliest join or check-in to now; a person with no check-out is counted to the unit's check-out, the period's end or now and marked `inferred`. `dev/test-hours.mjs` covers it.
- ICS-100 (v24; `ic_periods.pio` / `liaison`, `ic_period_agencies`, `ic_commands`, `ic_zones.branch`, `ic_members.kind`, js/shared/briefings.js): the briefings are assembled from the data, never typed, in `briefings.js` (no DOM; it takes the data module's read API, and `dev/test-briefings.mjs` passes a stub with the same methods). Who holds command is `ic_commands`: the first Incident Commander named on a period establishes it (`ic_period_command` trigger), a changed name on a plain save is a correction and renames the open row ("Just change the name"), and a handover goes through `ic_transfer_command(p_incident, p_to, p_notify, p_at, p_ops)`, which closes the old row, opens the new one, changes the period's seats quietly (`ic.quiet`, so `ic_log_period` stays silent), writes the notable "Command transferred from A to B" line and sends the safety-style message every unit acknowledges; the words are `ic_transfer_text` in SQL and `transferText` in rules.js, and `p_at` is the base's local clock because the server has no time zone. The base asks with `#transfer-dialog` (`askTransfer` / `doTransfer` in js/base/main.js) whenever the IC's name changes on the period form or a period starts with a different one; the pending save waits in `state.transfer`.
