# CLAUDE.md

Guidance for Claude working in this repo. README.md says what the app is and how to run it.

## Product rules

- **Two views, one truth.** The base (`index.html`) and the field app (`field/`) share `js/shared/`: `rules.js` (no DOM, no network: headings, zone codes, polygons, statuses), `data.js` (the only module that talks to Supabase) and `queue.js` (the field's outbox). A rule that both views must obey goes in `rules.js` or in the database, never in one view.
- **The database writes the log.** `ic_events` (the ICS 214) is filled by triggers on zones, photos, hazards, alerts and the incident. The apps insert only `note` events. If you add a kind of thing a unit can send, add its trigger in a migration.
- **Nothing is deleted.** Hazards are resolved, alerts are stood down, incidents are closed, zones are reopened. There is no delete path, and RLS has no delete policy.
- **Field first.** Every field action is one or two taps, works with gloves and rain, and goes through the outbox so a dead spot never loses a report. Ids are made on the phone before queueing, so a retry is harmless.
- **Heading is part of a photo.** A photo carries the compass heading at the moment it was taken; the base draws the wedge. Never drop it to simplify.

## Stack

- Plain JavaScript ES modules, no build step, hosted as a static site. Leaflet 1.9.4 from cdnjs; the service worker caches it on first use.
- Supabase project `cjwybuhogxyayjnuxpem` (charity-tooling), shared with the charity app. Every table, function and policy of this app carries the `ic_` prefix. Owner-only RLS by incident membership: `ic_is_member(incident_id)` / `ic_is_ops(incident_id)`. The photo bucket is `ic-photos`, private, read through signed URLs.
- Apply migrations with `python3 dev/sbq.py supabase/migrations/<file>.sql` (the Management API with the Supabase CLI's saved login) and keep the file in `supabase/migrations/`. Rule tests go in `supabase/tests/` and must roll back.
- `config.js` is committed and holds only the public publishable key. Never put a secret key in it. Local overrides go in `config.local.js` (gitignored, localhost only).
- Sign-in is Supabase email and password. Field units check in to an incident with its six-letter code (`ic_join`); Operations creates incidents (`ic_create_incident`).
- Mock mode: `?mock` on localhost loads `dev/mock-supabase.js` before `supabase-client.js` (two lines in `index.html` and `field/index.html`, the only hook in the real app). It stands in for Supabase in memory, mirrors the migration's triggers (`afterInsert` / `afterUpdate`), column defaults (`DEFAULTS`) and policies (`allowed`), and seeds Cedar Fork Flooding with the base signed in as Operations and the field as Unit 3. Claude's browser pane cannot sign in to the real project (the credentials would go to Supabase), so this is how anything behind sign-in is exercised. When a migration adds a table, a column with a default, a trigger or a policy, mirror it in the mock and give the seed a row that uses it; when `data.js` gains a supabase-js call, add it to the builder. README.md says how to run it.

## Every release

1. Bump `VERSION` in `sw.js` when any shell file changes (cache-first). Add new JS or CSS files to `SHELL`.
2. `npm run check` (`node --check` on every JS file) and `npm test` (`dev/test-rules.mjs`, for `rules.js`). For anything the views do, run the smoke test against the mock: open `http://localhost:8766/?mock` at desktop width (1280 wide) with no other mock tab open, and in the console `const { run } = await import('/dev/smoke.js'); await run()`. It takes about 20 seconds; in the Browser pane start it detached (`import('/dev/smoke.js').then((m) => m.run()).then((r) => { window.__smokeResult = r; })`) and read `window.__smokeResult`. The pane must stay visible: the base redraws on `requestAnimationFrame`, which a background tab never gets.
3. Apply any new migration before pushing: the apps read the new columns on start.
4. Commit messages: a release is titled after the feature with the version in parentheses, matching `sw.js`.

## Gotchas

- GPS, camera and compass need a secure context: `localhost` or HTTPS. A LAN `http://` address on a phone gives none of them.
- iOS gives compass readings only after `DeviceOrientationEvent.requestPermission()` from a tap; `Sensors.requestCompass()` is called before the camera opens and from the menu.
- The camera is a file input with `capture="environment"`; the heading recorded is the compass reading when the picture comes back, not when the shutter was pressed.
- Realtime subscriptions use one filter per table (`incident_id=eq.<id>`); the incident row itself is filtered by `id`.
- Leaflet markers are `divIcon`s with `iconSize: [0, 0]`; CSS centres the marker on the point. Unit markers are kept and moved, everything else is redrawn on change.
- GitHub Pages serves the site from a subpath, so every link and import is relative; the field app registers `../sw.js`.
- Messages (`ic_messages`, `ic_message_acks`; ROADMAP slice 1): recipients are fixed on the message as `to_users` when it is sent (`Data.recipientsFor('all' | 'ops' | 'zone:<id>' | 'user:<id>')`), one ack row per recipient with a reply. `kind` is `message`, `safety` or `par`; a safety message takes over the phone until acknowledged and stays on the base's yellow bar (`openSafety()`) until every recipient has answered. Log kinds are `msg`, `safety`, `par`; log rows carry the class `log-<kind>` because the plain `.msg` class is the form message in shared.css.
- Accountability (ROADMAP slice 2): `ic_members.status` is `assigned`, `available`, `out_of_service` (with `status_note`) or `checked_out`, with `status_at`, `crew_count` and `agency`. The database sets it from assignments (`ic_zone_sets_status`), stamps and logs every change (`ic_member_before` / `ic_member_after`, log kind `status`), and a check-out gives the unit's zones back. A unit may update its own row, Operations any row. The PAR is a message of kind `par`; the answer is an ack with `reply` "All accounted for" or "Missing someone" and `count`; a missing report also raises an alert from the phone. Labels live in `rules.js` (`STATUS_LABEL`, `OOS_REASONS`).
- Operational periods (ROADMAP slice 3): `ic_periods` and `ic_objectives`; `ic_incidents.current_period_id` points at the open one and `ic_zones.objective_id` at the objective a zone serves. `ic_start_period` (ops only) closes the current period, carries open objectives into the new one renumbered from 1 and moves the zones with them, quietly (`ic_quiet()` reads the `ic.quiet` setting so the objective trigger stays silent); `ic_create_incident` opens period 1. `periodLabel()` in rules.js names a period the same way everywhere. The briefing is `briefingSections()` in js/base/ui.js, rendered as a page and as plain text from the same lines; `@media print` in base.css prints only `#briefing`.
- The Division assignment (ROADMAP slice 4): `ic_zones.work_assignment`, `instructions`, `channel`, `supervisor`; the log says "Division B-2 drawn" and "B-2 assignment updated". The printed 204 (`form204Sections` in js/base/ui.js) shares the briefing overlay: `state.printZone` picks which to draw. In code and the database a division is still a zone (`ic_zones`, `zone`); only the words on the base changed.
- Search passes and structures (ROADMAP slice 5): `ic_zones.status` is `open`, `active`, `primary` (primary search complete) or `cleared` (secondary complete), stamped by `ic_zone_stamps`; a finished pass frees the unit like a clear. `ic_structures` is one record per address; `ic_structure_after` makes the zone's `cleared` the count of searched records and `structures` at least the record count, so once a zone has records the old tap counter is gone, and logs a notable record (people needing help, sheltering or refused, major damage, hazards). `Data.finishPass(zoneId, pass, {marking})` is how both views finish a pass. The field's "Address clear" is `openStructure()`; a structure placed from the base is `not_searched` until the field taps it.
- Facilities and the communications plan (ROADMAP slice 6): `ic_facilities` (kind, name, position, contact, notes, `closed_at`), ops only, logged by `ic_facility_after`; `ic_incidents.channels` is a JSON list of `{use, channel, notes}` logged by `ic_log_incident`. `FACILITY_KINDS` in rules.js carries the letter drawn on the map; `nearestFacility()` and `directionsUrl()` are what the phone uses. Placing is the map's `facility` mode: one click, then the panel opens to name it.
- Reports (ROADMAP slice 7): `ic_periods.sitrep` holds the situation report's words (`summary`, `needs`, `outlook`), logged by `ic_log_period`. One overlay (`#briefing`) draws the briefing, a division's 204, the situation report or the IAP: `state.print` picks which, `sitrepSections` / `iapSections` in js/base/ui.js build them from the same section lists as the briefing, and `.no-print` keeps the edit form off the paper.
- Both views redraw once per animation frame while frames are coming, and at once when none has come for 1.5 s (`queueDraw`, `lastFrameAt`): a hidden Browser pane or a background tab gets no frames, throttles its timers, and may not even report `document.hidden`; the smoke test depends on the page drawing.
- The field's home screen keeps the action buttons above the mini map so they stay reachable when a banner and a message card are showing; the mini map has `position: relative; z-index: 0` so Leaflet's own z-indexes stay inside it and the sheets cover it.
- The mock's tabs only share data with tabs on the same `SEED_VERSION` (dev/mock-supabase.js): bump it when the seed or the tables change, or a tab left open on older code hands a fresh tab tables the new code cannot load, and the page falls back to the picker. The mock's data is per tab. A tab that opens beside another mock tab copies that tab's data over the BroadcastChannel; `window.__mock.reset()` reseeds this tab only. The smoke test resets before each suite and reopens the incident through the page's own `open-incident` click handler (a synthetic button), because `js/base/main.js` exports nothing; keep that action. The mock also replaces `navigator.geolocation` with a pretend phone (`window.__mock.geo`), so the field tab shares a position without a device.
